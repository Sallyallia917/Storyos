# StoryOS 评测与 V0.3 A/B 回归

## 本轮目的

只验证三个已识别的失败模式，不把“输出更长”或“更像故事”当成质量提升：

1. **选择空间幻觉**：是否把理论可想象的选项误当成当时真实可行的选项。
2. **事实/推断混淆**：是否把动机、恐惧、因果解释或未经核验的来源写成事实。
3. **结构诱发补全**：证据不足时是否仍强行补齐字段、选项或因果链。

## 如何运行

在项目根目录执行（确保已安装 requirements.txt，且设置了 DeepSeek API Key）：

```bash
pip install -r requirements.txt
pip install pytest
export DEEPSEEK_API_KEY="你的真实密钥"
pytest -q
python evaluation/run_ab.py "杨康"
```

Windows PowerShell 设置密钥：`$env:DEEPSEEK_API_KEY="你的真实密钥"`

A/B 脚本对同一个对象分别调用 baseline 和 V0.3，各调用一次 API。结果写入 `evaluation/outputs/ab_latest.json`。每次运行会覆盖该文件，需要保留历史结果时先复制并改名。不要把密钥写进代码或提交到 Git。

切换应用版本：
- 默认使用 V0.3。
- `STORYOS_PROMPT_VERSION=baseline` 使用旧提示词。
- `STORYOS_PROMPT_VERSION=v03` 使用 V0.3 提示词。

## 人工评分量表（每项 0–2 分，分数越高越好）

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 选择可行性 | 明显不可能或纯理论选项被当成真实选项 | 部分说明条件，但仍有关键缺口 | 每个选项说明当时必要条件和限制；证据不足时排除或标明不确定 |
| 事实与推断边界 | 推断/心理被当成事实，或伪造来源 | 有区分但不一致 | 事实有可核来源；动机/因果推断显式标注；来源不确定时承认 |
| 不确定性校准 | 无依据仍肯定断言 | 偶尔表达不确定，但仍强行补全 | 可用 null/空数组/明确不确定表达，不为填字段编造 |
| 因果链完整性 | 从选择跳到远期结局，关键环节缺失 | 有链条但局部跳跃 | 区分即时情境、直接代价和远期结果，缺口明确指出 |

## 比较原则

- 同一对象、相同模型名、temperature=0.2、相同输入，只改变 prompt 版本。
- 大模型存在随机波动；单次 A/B 只能作为初步观察。若出现明显差异，重复一次同对象测试再判断是否稳定。
- 不要将历史报告中的评分直接与本轮结果相加；历史输出可能没有完整原始记录，且不是这次相同条件下重跑的结果。
- 本次先测一个对象，建议用“杨康”做首轮压力测试；确认流程稳定后，再加“令狐冲”作为不同人物的复测。
